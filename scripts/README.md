# scripts 目录说明

这个目录只保留当前还可能复用的工程脚本。历史的 `matcher_algorithm_iteration_agent*`、旧 presentation 生成器、旧 fixed/extreme 对比入口已经移除；那些结论仍保留在历史 `runs/`、`progress.md` 和 `task_plan.md` 里，不再作为可执行维护入口。

运行这些脚本时通常使用：

```bash
PYTHONPATH=python:scripts /home/xjw/.local/share/mamba/envs/plascan/bin/python scripts/<script>.py ...
```

## 训练与 lazy 数据流

| 脚本 | 用途 | 保留原因 |

| `benchmark_lazy_pose_pairs.py` | 从 pose render manifest 在线构造训练 pair；`--pair-mode spatial-index --spatial-index-height-km 100,250` 用 TSAI 相机 footprint 建空间索引并只纳入 100/250km 高度，`overlap-list --overlap-scan-all` 可生成固定重叠边 CSV，`--overlap-resume` 可在已有边/metrics CSV 后续跑，`train` 模式可用 `--pair-spec-manifest` 直接读取，且 manifest 模式会按 `--shuffle --seed` 打乱训练顺序。`--stable-graph-matcher-training` 的自动评估默认使用 `--visual-geometry-filter local --visual-geometry-threshold-px 10`，并把 inline false mining 设为 graph matcher + local10 + truth-wrong 目标；自动 visual eval 可用 `--visual-post-filter-profile true_geometry_error5_overlap10` 启用真实 depth/camera `error_px<=5` 且 `valid_fraction>=0.10` 的 filtered 口径，用于 Phase44 之后的 extreme/cross-camera 诊断。Phase 1 matcher calibration 默认使用 `--matcher-candidate-topk 256`、`--matcher-reliability-pair-bias off`、`--matcher-reliability-dustbin-bias off`、`--matcher-final-accept-score-mode none`、`--graph-matcher-metadata-mode calibrated`，GraphMatcher 输出匹配按 `pair_logit - row_dustbin - col_dustbin` 的 mutual-best margin 保留，不再用 dual-softmax 概率直接和 dustbin probability 比较。`calibrated` metadata 会清掉 matchability、descriptor uncertainty 和 no-match-prior 三类 reliability shortcut，只保留位置、几何与局部对比度进入 matcher。自动 visual eval 可用 `--visual-eval-every-steps` 在训练中每 N step 输出 `visual_report_step_XXXXXX/`，并把 filtered precision、pair recall、RANSAC inlier count、match count 分布和 extreme 子集指标写入 `train_metrics.csv`；训练日志还会记录 `dustbin_logit_for_true_match_mean`、双 dustbin margin 分布和 `true_match_in_topk@64/@256`。训练遇到 non-finite loss/gradient 默认跳过该 step，可用 `--no-skip-nonfinite-steps` 恢复直接报错。`--keypoint-offset-weight` 会监督 SparseHead 的亚像素 keypoint offset，并把 `keypoint_offset_loss`、`keypoint_offset_points` 写入 `train_metrics.csv`；`--selected-keypoint-offset-weight` 会在当前 heatmap 选出的 sparse keypoint grid 上用 warp 几何监督 offset，并写入 `selected_keypoint_offset_*` 指标，用于 Phase16 压 5-8px near-miss；默认会训练整个 keypoint head，诊断定位漂移时可加 `--train-keypoint-offset-head-only` 只训练 `sparse_head.keypoint_offsets.*`。`--visual-filtered-min-matches` 可把 RANSAC/MAGSAC 后 inlier 过少的 filtered 输出清零，当前 fov76 主链常用 16。训练保护可用 `--stability-max-dustbin-rejection-ratio` 和 `--stability-min-num-filtered-matches` 显式拦截 dustbin spike 与 filtered match 塌缩；loss explosion 需要同时超过 `--stability-max-loss-multiplier` 和 `--stability-min-loss-delta-for-explosion`，避免 hard-sample 训练因很小的绝对 loss 波动误停；`--stability-auto-recovery` 默认开启，触发后从 `last_good_pytorch_pfm_state.pt` 回滚模型、按 `--stability-lr-reduction-factor` 降低学习率，并受 `--stability-max-recoveries` 限制。可用 `--false-match-mine-matcher-mode`、`--false-match-mine-geometry-filter local|affine|ransac|magsac`、`--false-match-mine-geometry-threshold-px`、`--false-match-mine-source` 覆盖。`--train-graph-calibration-only` 只训练 GraphMatcher 的 accept/geometry bias/dustbin/logit scale 校准参数，冻结 attention 和投影层。`--graph-matcher-raw-false-match-weight` 会挖 raw descriptor 高相似的非对角错配边并压低对应 graph logit，不额外提高 dustbin 权重，常与 `--graph-matcher-raw-false-match-topk`、`--graph-matcher-raw-false-match-min-similarity`、`--graph-matcher-raw-false-match-margin` 配合用于减少 MAGSAC 前的重复纹理错配。`--graph-matcher-final-false-match-weight` 除了正样本 block 内 off-diagonal，还会把 graph/geometry mining 写入的 false pair 作为 mined false edge 按最终 `pair_logit - row_dustbin - col_dustbin` score margin 压低 pair logit/accept，dustbin 只 detach 参与比较，且这些 false endpoints 不参与 dustbin/no-match 监督；对应诊断为 `graph_matcher_mined_false_match_*` 和 `graph_matcher_extra_false_match_pairs`。`--graph-matcher-true-match-margin-weight` 会按最终 `pair_logit - row_dustbin - col_dustbin` 口径惩罚真匹配输给同行/同列竞争项的 false-negative，不提高 dustbin 权重，适合 fov76 extreme_02/extreme_03 低 raw match count 的 hard-mix 训练。`--graph-matcher-ransac-consistency-weight` 会用正匹配拟合几何模型，筛选残差超过 `--graph-matcher-ransac-consistency-residual-threshold-px` 且最终分数高的 off-diagonal edge，按 margin 压低其 pair/accept 分数；`--graph-matcher-warp-outlier-weight` 则直接用训练 pair 的 warp 真值，把 off-diagonal 目标点残差超过 `--graph-matcher-warp-outlier-residual-threshold-px` 且最终分数高的 edge 当几何错配压低，避免仿射/RANSAC 近似掩盖行星影像中的非仿射错配；两者 dustbin 都只 detach 参与分数，不增加 dustbin/no-match/rejection 监督。`--graph-matcher-warp-outlier-accept-weight` 使用同样 exact-warp outlier 候选，只对 accept logits 做负样本 BCE，不压 pair logits，用于把 accept head 训练成错配拒绝器。`--pair-spec-manifest` 中的 `false_cluster_*` 和 `true_geometry_*` 额外字段会保留到 `LazyPairSpec`；false-cluster replay 只放大 false-edge/warp-outlier 类 loss，不放大 no-match/dustbin 权重；true-geometry supervision manifest 的 `pair_accept_label` / `pair_accept_weight` 会进入 pair acceptance loss，`train_metrics.csv` 会记录 `false_cluster_replay_pairs`、实际 multiplier、`true_geometry_supervised_pairs`、accept/reject pair 数和 supervision weight 均值。 | 当前全量训练主入口，dashboard 训练也围绕它读取指标。 |
| `visualize_lazy_pose_matches.py` | 对 lazy pose pair 和 checkpoint 生成代表性匹配连线图；GraphMatcher 模式支持 `--graph-dustbin-delta`、`--graph-acceptance-margin`、`--graph-min-raw-score`、`--graph-min-raw-margin`、`--graph-min-accept-probability`、`--matcher-candidate-topk`、`--matcher-accept-assignment-mode add|off`、`--matcher-final-accept-score-mode multiply|none|add` 与 `--matcher-final-accept-score-alpha` 等推理过滤/候选阈值；其中 `--graph-acceptance-margin` 现在作用在 `pair_logit - row_dustbin - col_dustbin` 的 logit margin 上，`--matcher-accept-assignment-mode off` 可用于诊断 accept head 是否通过 assignment 压低召回，`--matcher-final-accept-score-mode multiply` 可用于诊断 accept head 是否能通过最终分数压低错配。`--use-keypoint-offsets` 会把 SparseHead 输出的亚像素 offset 用于关键点坐标、descriptor 双线性采样和 graph metadata/score 采样，用于检查 5px 阈值附近 near-miss 是否来自整数网格定位。`--geometry-filter local|affine|ransac|magsac|true_geometry` 可启用主口径几何后过滤，其中 `error_px<=5` 且 `valid_fraction>=0.10`。`--geometry-threshold-px` 可让过滤阈值独立于 5px 正确率判定，`--filtered-min-matches` 可丢弃 RANSAC/MAGSAC 后 inlier 数过少的 filtered 输出；`--filtered-min-matches-by-variant extreme_02=8,extreme_03=8` 可只放宽指定 target variant 的 min-match gate，用于 fov76 extreme-only 后验扫描；`--post-filter-profile fov76_geo5_geo10_extreme_rescue` 会把后处理展开为当前 fov76 推荐口径：主过滤 local/geo5、filtered `score_min`、`score_mean`、`score_median`、`score_max`，以及 `bbox_area_*`、`displacement_mad_px`、`homography_residual_*` 等推理侧几何诊断字段，用于判断低匹配 rescue 是否有足够 matcher 置信度和几何稳定性；`--write-all-summary` 会额外输出全部候选的 / `all_filtered_match_details.csv`，逐条记录 match 坐标、score、error、correct、`pair_logit`、两侧 `dustbin` logit、`positive_vs_dustbin_margin`、`raw_similarity`、`raw_margin`、`accept_logit` 和 `accept_probability`，用于对比 checkpoint 的新增/丢失匹配和定位 false positive 来源；`--no-write-all-match-details` 可在仍写 `all_filtered_match_details.csv` 的同时跳过 unfiltered `all_match_details.csv`，适合 true-geometry selector/promotion 这种只消费 filtered 明细的长评估；需要 fresh 负样本训练 match-detail scorer 时，可保留 unfiltered 输出并用 `--all-match-details-max-results`、`--all-match-details-max-matches-per-result` 控制 `all_match_details.csv` 体量，采样只作用于未过滤明细，`all_filtered_match_details.csv` 仍保留完整 true-geometry filtered 口径。 | 训练结束自动报告、历史训练页和阈值扫描依赖它；RANSAC/MAGSAC 是当前默认后验主链，`true_geometry_error5_overlap10` 是 Phase44 后用于深度/相机可用场景的 extreme/cross-camera 诊断口径。 |

当前 fov76 active 推理 profile 是 `fov76_geo5_geo10_extreme_rescue_lowmatch_guard`，active selector 证据链使用 `phase3zn_phase5g_selector_min16`：它等价于 `phase3zn + geo5 base + geo10 gain5 adaptive rescue + minmatch16 + extreme_02/03 low-match geometry guard`。旧的 `fov76_geo5_geo10_extreme_rescue` 保留为基础 rescue profile，用于复现 low-match guard 固化前的实验结果。训练内自动 visual eval 可通过 `benchmark_lazy_pose_pairs.py --visual-post-filter-profile fov76_geo5_geo10_extreme_rescue_lowmatch_guard` 使用同一口径；训练后 checkpoint 晋级评估可通过 `run_fov76_checkpoint_promotion_pipeline.py --post-filter-profile fov76_geo5_geo10_extreme_rescue_lowmatch_guard` 让 baseline/candidate 使用同一 active 后处理口径。

备注：`benchmark_lazy_pose_pairs.py` 的 `train` 模式支持 `--graph-matcher-warp-soft-boundary-weight` 及对应 `--graph-matcher-warp-soft-boundary-lower-residual-px` / `--graph-matcher-warp-soft-boundary-upper-residual-px`。该 loss 使用真实 depth/camera warp 残差，把 lower 到 upper 之间的 near-miss edge 训练成线性软目标，避免 5-8px 边界样本被 hard outlier 直接压成强负样本；诊断字段写入 `graph_matcher_warp_soft_boundary_*`。

备注：`benchmark_lazy_pose_pairs.py` 的 `train` 模式支持 `--training-crop-size` 和 `--training-max-image-size`，这两个参数会在每个 pair 进入 `train_step` 后再次作用到真实反传图像；`--crop-size` 仍主要控制 lazy pair 构造和自动 visual eval 的取样窗口。需要全模块训练但 DenseHead/quality path 显存过高时，优先用 `--training-max-image-size` 降低反传分辨率。

备注：`visualize_lazy_pose_matches.py` 和 `run_graph_filter_sweep.py` 支持 `--adaptive-geometry-rescue-variants`、`--adaptive-geometry-rescue-threshold-px`、`--adaptive-geometry-rescue-min-match-gain`、`--adaptive-geometry-rescue-max-base-matches`、`--adaptive-geometry-rescue-max-homography-p90-px`、`--adaptive-geometry-rescue-max-homography-median-px` 与 `--adaptive-geometry-rescue-require-score-mean-not-lower`。该功能用于 fov76 extreme_02/extreme_03 的保守后处理：默认仍走主口径几何阈值，只对指定 target variant 额外计算一份更宽几何阈值的 rescue 结果，并且只在 base 低匹配、匹配数增益、推理侧 homography residual 和 score mean 门限都满足时替换 filtered summary。规则只使用推理可观测字段，不使用 correct/wrong/precision 标签；输出仍写入原 visual report 的 `all_filtered_summary.csv`、`filtered_summary.csv` 和 metadata，供 filter sweep 与 promotion gate 复用。

备注：`visualize_lazy_pose_matches.py` 和 `run_graph_filter_sweep.py` 支持 `--low-match-geometry-guard-variants`、`--low-match-geometry-guard-min-matches`、`--low-match-geometry-guard-max-matches`、`--low-match-geometry-guard-max-homography-p90-px`、`--low-match-geometry-guard-max-homography-median-px` 与 `--low-match-geometry-guard-min-score-mean`。该功能不是直接降低全局 minmatch，而是在默认 `--filtered-min-matches` 会清零的低匹配数区间内，只对指定 target variant 且 homography residual/score mean 足够干净的结果放行，当前用于 fov76 extreme_02/extreme_03 的 guarded low-match rescue。`run_fov76_checkpoint_promotion_pipeline.py` 同步支持 `--baseline-low-match-geometry-guard-*` / `--candidate-low-match-geometry-guard-*` 分侧参数，可在同一 checkpoint 上比较 active 后处理和 guarded candidate，避免把低门槛规则误作用到 protected baseline。

备注：`benchmark_lazy_pose_pairs.py` 的训练内自动 visual eval 现在默认向 `visualize_lazy_pose_matches.py` 传入 `--write-match-details`，周期报告会保留 `all_filtered_match_details.csv` / `filtered_match_details.csv`，并把 `visual_pair_logit_mean`、`visual_dustbin_logit_for_match_mean`、`visual_positive_vs_dustbin_margin_*`、`visual_accept_logit_mean` 等 matcher calibration 摘要写入 `train_metrics.csv`，便于直接追踪 visual subset 上的 dustbin/margin 分布。训练稳定性行还会写入 `nan_count`、`recent_loss_mean` 和 `recent_top1_mean`，对应 early-stop/recovery 使用的 rolling window。GraphMatcher 训练诊断中的 `dustbin_logit_mean` 是 `dustbin_logit_for_true_match_mean` 的兼容字段，均为 true match 两侧 dustbin logit 之和；`accept_logit_mean` 是 true-match 对角线 accept logits 均值；`false_match_accepted_ratio` 按最终推理分数 `pair_logit - row_dustbin - col_dustbin > 0` 统计正样本 block 内 off-diagonal false edge 被接受的比例，用于同时发现过度保守和过度放宽。

备注：`benchmark_lazy_pose_pairs.py` 和 `python/pfm_pytorch_training.py` 都支持 Phase4 descriptor geometry safety 参数：`--descriptor-geometry-blend-weight` 控制 original descriptor 与 geometry-aware pooled descriptor 的混合权重，`--descriptor-scale-log-clamp-min/max` 控制 geometry pooling 的 scale log clamp。默认 `blend=1.0, clamp=[-2,2]` 保持旧行为；`--descriptor-geometry-safety-schedule phase4` 会在训练中按进度自动执行 `0-20%: blend=0, clamp=[-0.7,0.7]`、`20-60%: blend 线性到 0.3`、`60-100%: blend 线性到 0.5, clamp=[-1.2,1.2]`，并把当前 blend/clamp 写入 `train_metrics.csv` 和 checkpoint/input summary。该开关用于防止尚未稳定的 orientation/scale/affine 头直接污染 descriptor pooling。

备注：`run_fov76_checkpoint_promotion_pipeline.py --post-filter-profile true_geometry_error5_overlap10` 会默认让 true-geometry selector validation 透传 `--required-variant extreme_01 --required-variant extreme_02 --required-variant extreme_03`；可用 `--true-geometry-selector-required-variants` 覆盖，传空字符串可关闭 variant-level gate。
备注：`benchmark_lazy_pose_pairs.py` 中 `--graph-matcher-no-match-points N --graph-matcher-no-match-weight 0` 会加入不带 dustbin 监督的上下文 distractor，只让正匹配在更接近推理的候选池里竞争，适合 fov76 extreme hard-mix 训练。
备注：`benchmark_lazy_pose_pairs.py --train-pair-accept-head-only` 只训练 `graph_matcher.pair_accept_head.*`，用于 pair-level accept/reject 诊断；它不会更新 GraphMatcher attention、descriptor projection、accept head、geometry bias 或 dustbin/logit calibration 参数。若 pair manifest 未打乱，pair-level BCE 很容易被连续 reject 样本推成全拒绝，训练这类 head 时应配合 `--shuffle` 或交错 manifest。

备注：`benchmark_lazy_pose_pairs.py --graph-matcher-true-geometry-match-count-floor-weight` 会读取 `--pair-spec-manifest` 中的 `true_geometry_positive_matches` 和 `true_geometry_supervision_weight`，把真实 depth/camera 产生的几何正匹配数量作为 GraphMatcher 训练下限；loss 按最终 `pair_logit - row_dustbin - col_dustbin` 分数要求对应数量的真实匹配超过 `--graph-matcher-true-geometry-match-count-floor-threshold + --graph-matcher-true-geometry-match-count-floor-margin`，并在 `train_metrics.csv` 写入 `graph_matcher_true_geometry_match_count_floor_*` 指标。该监督不读取 LightGlue 标签。
备注：`--graph-matcher-teacher-distillation-weight` / `--graph-matcher-teacher-distillation-temperature` 使用 `--graph-matcher-teacher-guard-state` 指向的外部 teacher checkpoint 做 GraphMatcher assignment 分布蒸馏；它用于 phase3y 这类“extreme 有收益但 formal/regression 回退”的 matcher-only 校准，目标是锁住 phase2h 的匹配分布，不增加 dustbin/no-match/rejection 权重。
备注：`--graph-matcher-teacher-score-floor-weight` 使用同一个 teacher checkpoint，按最终 `pair_logit - row_dustbin - col_dustbin` 分数保护 teacher 已经高置信的真匹配，避免后续 matcher-only 校准把正匹配整体压低导致 match/correct count 塌缩；它只惩罚 true-pair score regression，不增加 dustbin/no-match/rejection 权重，诊断字段为 `graph_matcher_teacher_score_floor_*`。`--graph-matcher-teacher-match-count-floor-weight` 进一步按 teacher 中超过 `--graph-matcher-teacher-match-count-floor-threshold` 的 true-pair 数量设置召回下限，只要求 student 的 true-pair top-K 超过 threshold+margin，不强迫逐点完全复制 teacher；诊断字段为 `graph_matcher_teacher_match_count_floor_*`，主要用于 phase6c 这类“正确匹配数量退化但不想加重 dustbin/rejection”的 matcher-only 小步训练。`--graph-matcher-teacher-match-count-ceiling-weight` 是对称的精度约束：只在真实 aligned positive count 范围内限制 student 超过 teacher 达标数量的额外 true-pair final score，避免 replay 追加的 aligned false pairs 污染 count ceiling；false-cluster replay 追加的错配仍由 mined false-edge、final false-edge 和 RANSAC-consistency loss 处理。诊断字段为 `graph_matcher_teacher_match_count_ceiling_*`。
备注：新实验优先用 `--graph-matcher-mined-false-match-weight` 单独消费 graph/geometry mining 写入的 false pair，压低 mined false edge 的 pair logit/accept，不必开启 positive-block `--graph-matcher-final-false-match-weight`，也不增加 dustbin/no-match 监督。`--graph-matcher-mined-false-match-loss-cap` 可限制少量极高分 mined false edge 造成的单步 loss 尖峰，避免 phase3q 这类 hard false 训练把整体 correct recall 压低。

备注：`--graph-matcher-mined-false-match-reference-margin` 默认 `-1` 表示关闭；设为非负值时，mined false loss 只训练最终分数接近或超过正匹配参考分数的危险 false edge，并把被跳过的安全 false edge 数记录到 `graph_matcher_mined_false_match_reference_filtered_edges`。这用于 phase3s 之后的保守 hard false 训练，避免继续压低已经明显低于 true match 的边。

备注：`--false-match-mine-target-variant extreme_02` 可把在线 false mining 限制到指定 target variant；可重复传参。`--false-match-mine-source valid_truth` 只挖 `valid_mask=True` 且重投影误差超过 `--false-match-mine-threshold-px` 的 false pair，避免把 invalid mask 或阈值边缘噪声当作 hard false；`truth_and_geometry_kept` 只挖 ground-truth 判错且没有被几何后验剔除的 false pair，适合专门压制 MAGSAC/RANSAC 后仍残留的重复纹理错配；输出的 `false_matches.csv` 会记录 reference/target base、variant 和 pair type，便于确认 hard false 来源。

备注：`benchmark_lazy_pose_pairs.py --mine-false-matches` 输出的 `false_matches.csv` 现在会写入 `lazy_pair_key`、reference/target dataset、pose、raw base、variant 和 crop 字段。`train` 模式通过 `--false-match-csv` 重新读取这些 CSV 时，会优先按稳定 `lazy_pair_key` 匹配当前 lazy pair，并在每个 step 内 alias 到临时 `lazy_pair_refs/step_*.pt` 路径；旧 CSV 如果只有 reference/target base 与 variant 元数据，也会按 legacy metadata key 尝试复用。这样 hard false labels 可以跨训练 run 重放，不再只能在挖掘当步消费。

备注：`--mine-false-matches` 现在只要求存在训练消费者；当 `--graph-matcher-final-false-match-weight > 0` 或 `--graph-matcher-mined-false-match-weight > 0` 且 GraphMatcher 训练开启时，即使 `--false-match-weight 0` 也会在线挖 graph/geometry false pair，用于直接训练 mined false-edge loss，避免被迫同时打开 descriptor false loss。graph-only mined false 训练如果没有显式设置 `--false-match-curriculum-max-probability`，默认挖掘概率会设为 1.0，避免开了 mining 但整轮训练不产生 false edge。
