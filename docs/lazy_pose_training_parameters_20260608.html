Lazy Pose 2048 训练参数说明

最后更新：2026-06-08。本文说明 scripts/benchmark_lazy_pose_pairs.py 当前 Python lazy pose 训练入口，尤其是 2048 原图训练、离线 overlap list、跨相机/跨 FOV pair 和拒配训练相关参数。

先看整体流程

当前训练拆成两个阶段，目的是避免训练时一边随机找重叠区域一边喂 GPU。

阶段模式输出/输入作用
1. 预处理 --mode overlap-list 写出 overlap_pairs.csv 读取 render manifest、TSAI 和 depth，筛出满足重叠阈值的 pair，并把两张图的固定 crop 窗口写入 CSV。
2. 训练 --mode train 读取 --pair-spec-manifest overlap_pairs.csv 训练时直接复用已验证的固定 crop，不再随机试错，因此 GPU 数据等待显著降低。

当前 run 的 overlap list 结果：2000 对，其中 same_position_view=1066、cross_camera=245、cross_fov=689，平均有效重叠约 0.6335。

当前 run 的核心配置

项目当前值说明
输入图像images_u8/*.tif使用 --image-source uint8，不是浮点 render 图。
图像尺寸2048 x 2048--crop-size 2048，当前图片本身也是 2048，所以等于整张图训练，没有再 resize。
depth2048 x 2048 float32用于几何投影、warp 和 valid mask，不作为模型输入通道。
AMP--amp --amp-dtype float16半精度训练，降低显存并提高速度。
激活重算--activation-checkpointing保存更少中间激活，反向传播时重算，省显存但增加计算时间。
显存约 17.6 GiB当前全模型 2048 微调在 RTX 4090 上的稳定占用，16G 显卡不能直接照搬。
GPU 利用率训练阶段中位数 100%使用固定 overlap list 后，最近训练 step 的 data_wait_ms 基本接近 0。

路径与运行控制

参数当前值作用常见调整
--render-manifestfov090 + fov110 两个 CSV训练数据索引，包含 pose_id/base_id/variant/split/lon_deg/lat_deg/tsai_path/image_path/depth_path。增加新数据集时追加 manifest 路径。
--output-dirtrain_output 或 overlap_preprocess保存指标、报告、checkpoint、GPU 采样。每次实验必须换新目录，避免覆盖。
--modeoverlap-list / train决定是生成 overlap CSV，还是开始训练。正式训练推荐先跑 overlap-list。
--pair-spec-manifestoverlap_pairs.csv预处理输出、训练输入。里面记录 pair 类型、图像 ID、valid fraction 和固定 crop 窗口。已有列表可复用，能保证训练 pair 可重复。
--init-pytorch-staterandom_pfm_state.pt初始 PyTorch 权重。当前是从随机初始化开始。微调已有模型时换成已有 checkpoint。
--steps20000训练 step 总数。smoke 用几十到几百；正式训练再加大。
--save-every-steps500每 500 step 保存 latest checkpoint。磁盘紧张可调大；长训练不要关。
--seed1234控制 shuffle、采样和增强随机性。对比实验保持一致。

数据和 pair 采样

参数当前值作用影响
--splittrain只使用 manifest 中 split 为 train 的记录。评估/验证时可换成 val/test。
--image-sourceuint8优先读取 uint8 图像路径。render 可读原 render 图，但 IO/归一化/显存压力可能不同。
--crop-size2048每个 view 输入模型的 crop 边长。显存最敏感参数。1024 会大幅省显存，但不再是 2048 训练。
--limit-pairs0 正式全量构建候选 pair 池后最多保留多少个候选；0 表示不截断。正式 overlap list 应使用 0。短测可临时设成较小值。
--overlap-scan-all正式开启overlap-list 模式逐一扫完整个候选池，把所有通过重叠阈值的 pair 写入 CSV。开启后 --pairs 只保留为兼容参数，不再限制输出数量。
--pairs抽样预处理才使用未开启 --overlap-scan-all 时，要抽到多少个有效 pair。2000 只能用于冒烟或 GPU 验证，不适合作为正式训练列表。
--pair-modespatial-index 正式图生成用 TSAI 相机 footprint 建空间索引，候选来自 3D bbox 相交，再交给投影重叠阈值精筛。训练消融仍可用 mixed、same-position、cross-camera、cross-fov。
--spatial-index-footprint-samples5每个相机 footprint 在图像平面每轴采样多少条 ray。越大 bbox 越保守但建索引稍慢；后续高度变化可直接通过相机中心和 ray 进入索引。
--spatial-index-margin-m2000对 footprint 3D bbox 额外外扩多少米，避免球面近似造成漏召回。越大候选越多，但不会漏掉边界附近的 overlap。
--spatial-index-height-km100,250构建空间索引前按 TSAI 路径或记录 ID 中的高度标记过滤。当前 overlap graph 只考虑 100km 和 250km；150km、350km 的 TSAI 会被跳过。预处理只纳入运行当时图像、深度和 TSAI 都存在的记录，拷贝中的数据应标记为 partial，最终训练前再重跑全量图。
--pair-type-weightssame=0.35,cross_camera=0.40,cross_fov=0.25构建候选池时不同 pair 类型的抽样权重。最终有效列表比例还会受实际重叠率影响。
--cross-camera-offsets1,2,4,8同 FOV 内跨相机位置，按 base 序列错开多少个位置配对。offset 越大，视角/位置变化越难，低重叠概率越高。
--cross-fov-offsets0,1,2跨 FOV 最近邻空间位置的第几个邻居。0 是最近邻；1/2 增加难度和多样性。
--cross-pair-variantnadir,small_01,mid_01,extreme_01跨相机/跨 FOV 时允许哪些视角 variant 相互配对。加更多 extreme 会增加难例，也会增加低重叠失败。
--reference-variant默认 nadirsame-position pair 的参考视角。通常保持 nadir。
--target-variant默认 small/mid/extreme 全部same-position pair 的目标视角列表。未显式传入时用脚本默认 9 个目标视角。

几何重叠筛选

参数当前值作用调参建议
--min-valid-fraction0.05crop 中至少多少比例像素有有效几何对应。提高会更干净但更难生成；降低会包含更多弱重叠样本。
--max-attempts8没有固定 crop 时，每个候选随机试几次 crop。overlap-list 预处理有用；训练读固定 crop 后基本只试一次。
--absolute-depth-tolerance-m100.0投影到目标图后，允许的绝对 depth 误差。DEM/render 深度噪声大时可适度放宽。
--relative-depth-tolerance0.005按深度比例允许误差，和绝对阈值取较大者。远距离场景更依赖这个值。
--skip-bad-pairs开启遇到低重叠/读图失败候选时跳过，不中断任务。正式预处理建议开启。
--max-bad-pairs50000 预处理阶段最多允许跳过多少个坏候选。跨 FOV/极端视角多时必须加大。

DataLoader 和 CPU 预取

参数当前值作用影响
--workers预处理 8，训练 6并行读取图像、depth、TSAI 并生成 pair 的进程数。太低 GPU 等待；太高会增加 CPU/内存/磁盘压力。
--prefetch-batches预处理 16，训练 12提前排队多少个 pair 生成任务。提高可平滑 GPU 供给，但增加内存和进程占用。
--worker-cache-items32每个 worker 缓存最近读取的 image/depth/camera。提高可减少重复 IO，但会增加 CPU 内存。

当前固定 overlap list 训练后，最近训练 step 的 data_wait_ms 基本接近 0，说明这一组参数已经足够喂满 4090。

显存和吞吐相关

参数当前值作用显存影响
--devicecuda使用 CUDA 训练。无。
--amp开启启用自动混合精度。显著降显存。
--amp-dtypefloat16AMP 使用 FP16。适合 RTX 4090/多数消费卡。
--activation-checkpointing开启反向传播时重算部分激活。显著降显存，代价是训练更慢。
--batch-pairs1每 step 几个 pair。2048 下必须保持 1，调大显存会爆。
--samples-per-pair128每个 pair 采多少个监督点用于 descriptor/graph/reliability。降低到 64 可省 GraphMatcher 和 loss 部分显存。
--max-grad-norm默认 1.0梯度裁剪，抑制不稳定 step。显存无明显影响。
--skip-nonfinite-steps开启遇到 NaN/Inf loss 时跳过该 step。显存无影响，提升长训稳定性。

训练哪些模型模块

这些开关决定哪些参数参与反向传播。参与训练的模块越多，显存和算力压力越大。

参数当前状态作用16G 建议
--train-backbone开启训练底层多尺度卷积特征。16G 首先关闭。
--train-dual-fpn开启训练 keypoint/descriptor 两路 FPN。16G 建议关闭。
--train-descriptor-head默认开启训练描述子输出头，是匹配核心。保留。
--train-sparse-context开启训练 sparse head 中上下文 tower。16G 不够时关闭。
--train-keypoint-head开启训练关键点 heatmap 和 offset。保留或按需求关闭。
--train-geometry-head开启训练尺度、方向、仿射等几何头。保留；若只做 descriptor 可关闭。
--train-texture-adapter开启训练纹理描述子适配模块。保留。
--train-descriptor-fusion开启训练 learned descriptor 和 texture descriptor 的融合。保留。
--train-quality-head开启训练特征质量相关输出。保留。
--train-reliability-head开启训练 matchability、uncertainty、no-match prior。保留。
--train-graph-matcher开启训练 GraphMatcher，包括 dustbin/no-match 逻辑。保留，但降低 attention work。

16G 显存建议档

当前 4090 全模型配置占用约 17.6 GiB，16G 机器建议保持 2048 输入，但冻结更大的前端模块，并降低 GraphMatcher 工作量。

改动原因
去掉 --train-backbonebackbone 激活最多，是 16G 首先要省的部分。
去掉 --train-dual-fpnFPN 也保留大分辨率特征，冻结可进一步省显存。
必要时去掉 --train-sparse-context上下文 tower 也会增加反向激活。
--samples-per-pair 64减少 descriptor/graph/reliability 监督点。
--graph-matcher-train-max-attention-layers 1减少 graph attention 层数。
--graph-matcher-train-max-attention-work-fraction 0.25减少 attention 工作量。
--graph-matcher-train-width-keep-ratio 0.5减少候选宽度。
--false-match-mine-max-keypoints 64 和 --false-match-mine-max-matches 64降低在线错配挖掘开销。
--reliability-negative-points 16降低 reliability 负样本数量。

不建议在 16G 上直接调大 batch-pairs，也不建议关闭 AMP 或 activation checkpointing。

最常改的参数

目标优先改这些不要先动这些
减少显存train-backbone、train-dual-fpn、samples-per-pair、GraphMatcher work 参数crop-size，除非接受不再用 2048。
提高 GPU 利用率pair-spec-manifest、workers、prefetch-batches、worker-cache-items不要在训练阶段继续在线随机筛低重叠 pair。
增加跨域数据pair-mode、pair-type-weights、cross-camera-offsets、cross-fov-offsets、cross-pair-variant不要只堆 same-position。
提升拒配能力enable-rejection-training、GraphMatcher no-match/dustbin 权重、reliability 权重不要过早把 hard/no-match 权重调得很大。
提升光照鲁棒性photometric-augment、local contrast、illumination consistency/match不要在基础匹配还不稳定时把光照增强开太猛。
提升旋转鲁棒性后续打开 rotation/orientation/scale/affine consistency 权重并做消融当前这次 run 这些权重是 0。
