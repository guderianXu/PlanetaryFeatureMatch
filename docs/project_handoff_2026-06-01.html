已经做了什么

1. PFM v2.1-full 模型架构

  • 已完成PyTorch 模型主路径升级到 256 维描述子，不是从 192 维投影到 256，而是 full 配置重新输出 256D descriptor。
  • 已完成加入 Dual-FPN-Lite，将 keypoint 定位特征和 descriptor 上下文特征分开。
  • 已完成Texture branch 改为更适合行星影像的光照鲁棒纹理特征，包括 local normalized intensity、local contrast、DoG/LoG、梯度方向、ring contrast、soft census-like 特征。
  • 已完成DescriptorFusionAdapter 改为局部 adaptive texture gate，不再只靠固定 texture weight。
  • 已完成GraphMatcherV2 支持 richer metadata、dustbin/no-match、raw preservation、hard-negative dustbin、semi-dense no-match 训练选项。
  • 已完成训练报告支持 raw_descriptor 与 graph_matcher 双口径，避免只看其中一种口径误判。

2. 训练流程与报告

  • 已完成训练报告已能生成中文 PDF、训练曲线、匹配质量图、覆盖率诊断图和匹配样例。
  • 已完成加入弱纹理 quota 和空间均衡采样：--training-weak-texture-fraction、--training-spatial-bins，用于缓解“旱的旱死，涝的涝死”。
  • 已完成训练 pair 每步监督点数已改到 --samples-per-pair 512。
  • 已完成增加数据集校验脚本 scripts/verify_pair_cache_dataset.py，训练前可检查 split 数量、比例和样本是否能加载。

3. 当前关键结论

  • 模型不是完全没学到东西；raw descriptor 在很多同位置/普通仿真 pair 上已经很准。
  • GraphMatcher 曾经明显“压坏” descriptor，特别是在极端跨位置样本上，因此后续训练要继续保留 raw/graph 双报告。
  • 弱纹理和空间均匀性已经开始通过训练采样解决，但这需要在新 10479 + cross/extreme 混合数据上再跑完整训练验证。
  • 传统 RootSIFT/ORB/AKAZE + 几何过滤在部分人工仿真对上非常强，因此它们更适合作为教师标签或 fallback 参考，不能把外部 matcher 的结果误报成 PFM 本身进步。

4. 跨相机位置数据

跨位置数据用 scripts/generate_cross_position_pose_pairs.py。核心逻辑是复用已有同位置仿真 archive，读取 CameraA 的真实渲染 depth，再把 A 时刻的地表点反投影到世界坐标，并重投影到另一个相机位置，形成 dense warp。

cd /home/xjw/code/deeplearning/PlanetaryFeatureMatch

python scripts/generate_cross_position_pose_pairs.py \

  --depth-mode rendered \
  --train-offsets 1,2,4,8 \
  --val-offsets 1,2,4,8 \
  --test-offsets 1,2,4,8 \
  --sat-sim 辅助软件/数据模拟/build/sat_sim_cuda \
  --dem 辅助软件/数据模拟/dem/mar.tif \

训练数据内部格式

每个训练 pair 通常是一个 pair_*.pt，旁边有对应 pair_*.json。目录结构一般是：

cache/
  train/
    source_xxx/
      pair_xxx.pt
      pair_xxx.json
  val/
    source_xxx/
      pair_xxx.pt
      pair_xxx.json
  test/
    source_xxx/
      pair_xxx.pt
      pair_xxx.json
manifests/
  *.csv
字段 作用
view_a, view_b 灰度影像张量，目前 2048×2048；训练时通过参数裁剪/缩放到 1024。
warp_a_to_b A 图像像素到 B 图像像素的真值对应，用于采样监督点和判断匹配正确/错误。
valid_mask 哪些 A 像素有有效投影和可监督对应。
pair_*.json 记录 pair 名称、视角、轨迹、难度等辅助信息。训练和报告会用它做 difficulty/pose 诊断。
manifests/*.csv 记录 split、pair 路径和生成元信息，重分区/校验/追踪数据来源时使用。

后续还应该造什么数据

优先级 数据类型 为什么需要 建议做法
P0 跨相机位置 train/val/test 完整版 实际任务不会只发生在同一个相机位置。不同位置能提供更真实的视差、尺度和可见性变化。 基于 10479 同位置源数据继续生成 cross-position rendered depth pair，保留 7:2:1 split，确保 train/val/test 都有数据。
P0 更极端 cross-position / ultra offset 当前模型在极端跨位置上仍是短板，需要覆盖更大 baseline、低重叠、局部可见性变化。 把 8T 上已有 ultra depth/probe 转成正式 pair cache；offset 可以覆盖 8、16、28 或按轨迹间距分桶。
P0 弱纹理/低对比区域专项 用户指出弱纹理匹配点仍少且空间分布不均。只靠随机采样容易被强纹理地貌主导。 按 local contrast / gradient energy / valid area 分桶采样，专门保留低纹理平原、阴影内部、低梯度区域。
P1 光照差异专项 行星影像强光照差异来自太阳高度角、方位角、坡面阴影，普通亮度增强不够。 如果仿真程序支持不同太阳方向，生成 same geometry + different illumination；否则先做 photometric transform 压力集。
P1 terrain-heldout 测试集 随机 pair split 容易让训练和验证看到相近地貌，平均指标会偏乐观。 按轨迹段、经纬度 tile 或 DEM/DOM 地理区域划分，留出完全未见区域做 test。
P1 no-match / low-overlap / occlusion 数据 GraphMatcher 的 dustbin/no-match 需要真实拒配监督，否则会过度拒配或乱匹配。 生成部分非重叠、低重叠、阴影遮挡、目标区域不可见 pair；训练时单独统计 accepted/rejected precision。
P2 RootSIFT-HRANSAC 高置信伪标签 传统 matcher 在很多仿真全局几何场景很强，可作为 teacher，但不能替代 PFM 指标。 只从 train split 生成，过滤到高 precision、足够 inlier 的 pair；训练报告必须把 teacher/fallback 和 pure-PFM 指标分开。

数据空间和重复存储注意事项

  • xjw2T 当前剩余约 214G，不足以再放一个 700G 级完整同位置数据集。不要直接继续往 xjw2T 大量生成。
  • 8T 当前剩余约 3.8T，可以继续作为生成盘和中间缓存盘。
  • 同一批影像如果既保存 full pair archive，又保存 image_store，会产生明显重复。后续应优先用 compact cache / shared image store / hardlink / symlink 方案，最终训练盘需要自包含时再 copy。
  • 跨盘不能可靠 hardlink；同盘归档可用 hardlink 或 symlink，跨盘训练拷贝建议用 repartition_pair_cache.py --link-mode copy --skip-existing 做可恢复 copy。
  • xjw2T 之前多线程 copy 出现过 I/O 问题，最终是 workers=1 --skip-existing 完成的。后续如果复制不稳定，先降低 workers，不要重复从头拷贝。
