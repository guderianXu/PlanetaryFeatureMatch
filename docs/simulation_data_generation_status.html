4. 关键脚本和职责

文件 职责
辅助软件/数据模拟/mars_orbit_to_tsai.py 把轨迹 CSV 转成 TSAI 相机文件，支持相机姿态扰动、焦距缩放、渲染脚本生成。
辅助软件/数据模拟/batch_pose_sim_dataset.py 批量生成 same-position 数据：渲染 CameraA 与同位置虚拟相机，转成 PFM pair cache。
辅助软件/数据模拟/pose_sim_to_pfm_cache.py 把 image、depth、TSAI 转成 pair_*.pt，写入 view_a/view_b/warp_a_to_b/valid_mask。
scripts/generate_cross_position_pose_pairs.py 基于 same-position 数据和 CameraA depth，生成不同相机位置的 cross/extreme pair。
scripts/compact_pose_sim_pair_cache.py 把 pair 中重复影像移动到共享 image_store，减少重复存储。
辅助软件/数据模拟/build/sat_sim_cuda CUDA 版渲染程序，输入 DEM、DOM、TSAI，输出仿真影像和 depth。

5. 制作链路

  1. 准备 DEM、DOM、SPICE kernel、相机轨迹 CSV。
  2. 用 mars_orbit_to_tsai.py 生成各轨迹、各扰动视角的 TSAI 相机文件。
  3. 用 sat_sim_cuda --write-depth 渲染仿真影像和 depth。
  4. 用 pose_sim_to_pfm_cache.py 把影像、depth、TSAI 转成 PFM 训练 pair。
  5. 用 generate_cross_position_pose_pairs.py 基于真实 rendered depth 生成跨相机位置 pair。
  6. 检查 manifest、valid fraction、pair 数量、corrupt pair。
  7. 必要时用 compact_pose_sim_pair_cache.py 去重影像存储。
  8. 把最终 cache/train|val|test 加入训练命令。
cross-position 数据必须优先使用 --depth-mode rendered。早期的 sphere 或 warp-or-sphere 只适合作为历史对照，不建议作为正式训练 GT。

8. 质量检查清单

  • 检查 dataset_metadata.json，确认 DEM、DOM、sat_sim、offset、min-overlap、split 数量正确。
  • 检查 manifests/*.csv，确认 train/val/test 划分符合 7:2:1 或本轮设计目标。
  • 检查 low_overlap 数量。极端数据允许较多低重叠候选被丢弃，但最终 kept pair 必须满足阈值。
  • 检查 corrupt_pairs。发现半写坏文件后必须移走，不要混入训练。
  • 每次新增数据至少抽样生成 10-20 张匹配可视化，看绿线/红线是否符合 GT。
  • cross-position 必须用真实 depth 和 TSAI 重投影生成 warp_a_to_b，不要用 RANSAC 或 matcher 输出反推 GT。
  • 训练前确认数据位于高速盘或已做缓存；机械盘会让 GPU 利用率上下波动。
  • 不要只看随机验证集平均 precision，要固定追踪难样本，例如 pair_004541_cross_off008_s00109_s00119.pt。

9. 重要注意事项

不要删除 image_store。compact 后的 pair_*.pt 可能引用共享影像文件，删除后 cache 会不可用。
不要把 runs/、训练数据/、大体积 .pt/.pth/.tif/.pdf/.png 推到 GitHub。GitHub 只保存脚本、文档和小型测试。
当前普通 cross_position 缺少 test split。下次扩数据时应优先补齐，而不是只继续加 extreme。
pose_sim_cross_position_rendered_extreme_2048_gap30_views10_721_v2 的 metadata 记录 test 目标为 600，但当前实际 find 到 599 个 pair，可能有一个坏 pair 被移走或未同步。后续正式报告前应核对 manifests 与实际文件数量。
当前使用的 rendered depth 链路是正确方向：DEM/DOM + TSAI 生成物理一致的影像和 GT warp，比人工造点或 matcher 输出更可靠。

10. 后续建议

  1. 优先补普通 cross_position 的 test split，至少 300-500 pair，最好 1000 pair。
  2. 把普通 cross_position train 从 1200 提高到 3000-5000 pair。
  3. 建立 terrain-heldout 测试集：测试地貌区域不要和训练区域重叠。
  4. 保留固定 hard case 报告：低重叠、off012/off016/off020/off024/off032、弱纹理、真实 TIFF。
  5. 如果继续扩到 30000-50000 pair，必须先做好去重、manifest、硬盘空间和训练读取缓存，否则 GPU 会被 IO 拖慢。
